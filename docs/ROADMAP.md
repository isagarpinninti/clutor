# Roadmap

Each milestone ends with something checkable. Dates are not promised; order is.

1. **Verified foundations (done).** Real OLMoE forward pass; golden test against an independent implementation; fuzzed file readers; CI jobs for both; `clutor generate` and `clutor quality`; benchmark write-up against Colibri and AirLLM.
2. **A model larger than RAM (mostly done).** Qwen3-30B-A3B Q4_K_M (17.3 GiB on a 16 GiB machine) runs: Qwen3-MoE forward pass and tokenizer built; parity with llama.cpp shown (identical tokenization, 96.7-98.0% router agreement, identical 24-token greedy continuations on three prompts); out of core at 2.0-3.0 tokens/s with 2.9-8.1 GiB resident. Pre-registered checks passed: peak RSS under 8 GiB at the 2 and 4 GiB caches, top token on all 6 prompts, routing agreement above 95%. **Still open:** the speed comparison against llama.cpp memory-mapping (the benchmark was stopped while llama.cpp loaded the file, so no win or loss is claimed), and an explanation of why token logprobs differ more than on OLMoE.
3. **Install story (built, partly verified).** 0.2.0 is released: `@clutor/core` and `@clutor/cli` on npm, and a GitHub release with engine binaries for macOS arm64 / Intel and Linux x64 / arm64 plus SHA256SUMS. `clutor engine install` was run end to end against the real release on macOS arm64. **Still open:** the installer on Intel macOS and Linux, `clutor pull` used for a live model download (it is unit-tested only), and a single documented command from nothing to generated text.
4. **Fewer bytes per token.** The router-ahead predictor is built and measured (82% of its picks are chosen, but it does not cut time on a bandwidth-bound run: docs/NATIVE_ENGINE.md); next, a cache policy compared on real traces; lower-bit expert variants only with their quality cost measured.
5. **A sixth architecture** (DeepSeek-style with latent attention, YaRN rotary scaling and shared experts, or Mixtral-style with a SentencePiece tokenizer). Five work today (`olmoe`, `qwen3moe`, `granitemoe`, and the dense `qwen2` and `llama`). Llama's `rope_freqs` factors and BOS handling are in place; DeepSeek would still need latent attention and YaRN.
6. **Invite others in.** A `clutor report` JSON format and a results table for benchmark submissions from other hardware; good-first-issue labels; GitHub Discussions. None of this raises the community score until others use it.

Not planned: training. The desktop app exists now (`app/`). GPU backends are not built; the place one would plug in, and what it would take, is in [DIRECTIONS.md](DIRECTIONS.md).
